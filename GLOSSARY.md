# Glossary

> Every term the course introduces, defined the way its lesson first teaches it, with a link to that day.
> Generated from each lesson's **New terms** list (At a Glance). Definitions are plain-language; *SWE:* gives a software-engineering analogy where one helps.


## A

- **A2A**: An open protocol, not a framework, that lets one agent talk to another agent across vendors and runtimes, complementing MCP, which connects an agent to tools. *SWE: ≈ HTTP between services, but for agents* — first taught in [Day 57](Phase_6_Agents/Day_057_agent_frameworks/agent_frameworks.md)
- **abstention**: The system declines to answer with "I don't know" when retrieved text doesn't support an answer, instead of guessing; track it on answerable questions too. — first taught in [Day 28](Phase_3_RAG/Day_028_rag_pipeline/rag_pipeline.md)
- **acceptance check**: A small plain-Python function that returns pass or fail for one rule of the output contract, so prompt changes are judged by tests, not opinion. *SWE: ≈ a unit-test assertion for model output* — first taught in [Day 9](Phase_2_Building_with_LLM_APIs/Day_009_effective_prompts/effective_prompts.md)
- **accuracy**: The share of answers that are right on a labelled set of inputs with known answers; the single number used to compare prompts. — first taught in [Day 10](Phase_2_Building_with_LLM_APIs/Day_010_few_shot_prompting/few_shot_prompting.md)
- **ACL filter**: A search filter that returns only rows the caller's groups may read, applied inside the query before ranking and failing closed when unsure. *SWE: ≈ row-level security on a query* — first taught in [Day 27](Phase_3_RAG/Day_027_hybrid_search/hybrid_search.md)
- **actionable error**: A short JSON error with what went wrong and a hint on what to call instead, returned to the model so it can fix its next tool call. *SWE: ≈ an error message that names the fix* — first taught in [Day 36](Phase_4_Tools_and_MCP/Day_036_tool_design/tool_design.md)
- **adapter**: One module that alone imports a framework and converts to and from your own types, so framework version changes touch one file. *SWE: ≈ an anti-corruption layer* — first taught in [Day 56](Phase_6_Agents/Day_056_openai_agents_sdk/openai_agents_sdk.md)
- **agent**: A loop in which the model picks the next step (call a tool, read a result, decide whether to continue) until it decides the task is done. — first taught in [Day 1](Phase_0_Start_Here/Day_001_ai_engineer_role/ai_engineer_role.md)
- **agent-as-tool**: Multi-agent pattern where a specialist agent is called like a function and returns a string, so the caller keeps ownership of the final answer. *SWE: ≈ a function call to a sub-service* — first taught in [Day 65](Phase_7_Multi_Agent_Systems/Day_065_handoffs_agents_as_tools/handoffs_agents_as_tools.md)
- **agentic RAG**: RAG where the agent plans queries, retrieves several times and decides when it has enough evidence, instead of retrieving once and generating. — first taught in [Day 52](Phase_6_Agents/Day_052_agentic_rag/agentic_rag.md)
- **Agent / Runner**: In the OpenAI Agents SDK, an Agent holds instructions, tools and model config, and a Runner executes the loop, with a max_turns limit. *SWE: ≈ a config object plus the executor that runs it* — first taught in [Day 56](Phase_6_Agents/Day_056_openai_agents_sdk/openai_agents_sdk.md)
- **Agent Skill**: A folder with a SKILL.md (name, description, steps) and optional scripts that an agent loads only when a task matches its description. *SWE: ≈ a runbook loaded on demand* — first taught in [Day 60](Phase_6_Agents/Day_060_coding_agents_skills/coding_agents_skills.md)
- **AGENTS.md**: A Markdown file of project rules at the repo root that a coding agent reads automatically every session. *SWE: ≈ a CONTRIBUTING file for agents* — first taught in [Day 60](Phase_6_Agents/Day_060_coding_agents_skills/coding_agents_skills.md)
- **AI engineer**: An engineer who builds products on foundation models using model APIs, retrieval, evals and agent frameworks, rather than training models. — first taught in [Day 1](Phase_0_Start_Here/Day_001_ai_engineer_role/ai_engineer_role.md)
- **alias vs snapshot**: An alias is a model name that floats to newer versions; a snapshot is a pinned version that stays fixed until its shutdown date. *SWE: ≈ a :latest Docker tag vs a pinned digest* — first taught in [Day 7](Phase_1_How_LLMs_Work/Day_007_choosing_a_model/choosing_a_model.md)
- **anchors**: Labelled example cases placed in the judge prompt to calibrate it, kept strictly separate from the test set so scores stay honest. — first taught in [Day 46](Phase_5_Evaluation_and_Observability/Day_046_judge_validation/judge_validation.md)
- **ANN index**: An approximate nearest-neighbour index (such as HNSW or IVFFlat in pgvector) that searches fast but may miss a few true neighbours. *SWE: ≈ a database index that trades exactness for speed* — first taught in [Day 26](Phase_3_RAG/Day_026_pgvector_search/pgvector_search.md)
- **answer relevance**: A check that the answer actually addresses the question asked, even if it is true and well sourced. — first taught in [Day 30](Phase_3_RAG/Day_030_answer_evaluation/answer_evaluation.md)
- **anti-pattern**: A prompting habit that looks helpful but reliably makes results worse, usually paired with a better alternative. — first taught in [Day 9](Phase_2_Building_with_LLM_APIs/Day_009_effective_prompts/effective_prompts.md)
- **API key**: A long secret string that identifies your account and project; whoever holds it can spend your money, so keep it out of code. — first taught in [Day 2](Phase_0_Start_Here/Day_002_setup_first_call/setup_first_call.md)
- **API key auth**: Authenticating callers with issued keys, storing only a hash of each key and mapping a verified key to a principal, plan and scopes. *SWE: ≈ password hashing for service credentials* — first taught in [Day 83](Phase_9_Production/Day_083_auth_multitenancy_quotas/auth_multitenancy_quotas.md)
- **application cadence**: A steady target of three to five tailored job applications per week, editing your top resume bullets each time. — first taught in [Day 63](Phase_6_Agents/Day_063_career_checkpoint/career_checkpoint.md)
- **approval gate**: A function approve(call) -> bool consulted before any side-effecting tool runs; the default answer is no. *SWE: ≈ a manual approval step in CI/CD* — first taught in [Day 37](Phase_4_Tools_and_MCP/Day_037_robust_tool_execution/robust_tool_execution.md)
- **approval mode**: A coding-agent setting for how much it may do without asking you, chosen per task risk. — first taught in [Day 60](Phase_6_Agents/Day_060_coding_agents_skills/coding_agents_skills.md)
- **approval request / decision**: Two small Pydantic models: a request says what, why and until when; a decision says approve, edit or reject. — first taught in [Day 55](Phase_6_Agents/Day_055_human_in_the_loop/human_in_the_loop.md)
- **at-least-once vs exactly-once effect**: A resumed run may repeat a step (at-least-once); idempotency keys make its side effect happen only once (exactly-once effect). *SWE: ≈ idempotent retries in a job queue* — first taught in [Day 54](Phase_6_Agents/Day_054_langgraph_durability/langgraph_durability.md)
- **attack mutator**: A function that rewrites an attack payload with one technique (such as base64 encoding) while keeping its goal, used to widen red-team coverage. *SWE: ≈ a fuzzer's input mutation* — first taught in [Day 75](Phase_8_Safety_and_Security/Day_075_red_teaming_ci/red_teaming_ci.md)
- **attack success rate**: Successful attacks divided by attacks times repeats; the measured number that shows whether a prompt-injection defence works. *SWE: ≈ pass rate for a security test suite* — first taught in [Day 69](Phase_8_Safety_and_Security/Day_069_prompt_injection/prompt_injection.md)
- **attempt cap**: The maximum number of retries allowed for a failing call (here 3), plus a dollar cap, so retry loops stay bounded. *SWE: ≈ a retry limit* — first taught in [Day 17](Phase_2_Building_with_LLM_APIs/Day_017_semantic_failures/semantic_failures.md)
- **attention**: The mechanism that lets each token weigh and gather information from other tokens in the context through attention weights. — first taught in [Day 5](Phase_1_How_LLMs_Work/Day_005_transformers_attention/transformers_attention.md)
- **audit log**: An append-only record of who decided what, written once per request. — first taught in [Day 55](Phase_6_Agents/Day_055_human_in_the_loop/human_in_the_loop.md)
- **authorizer allowlist**: A callback SQLite runs for every table and column a statement touches, approving or denying each, used to make text-to-SQL read-only and scoped. *SWE: ≈ a DB permission check per column* — first taught in [Day 33](Phase_3_RAG/Day_033_text_to_sql/text_to_sql.md)
- **auto-instrumentation**: A library that patches another (such as the OpenAI SDK) so its calls create tracing spans with no tracing code from you. *SWE: ≈ an APM agent* — first taught in [Day 42](Phase_5_Evaluation_and_Observability/Day_042_tracing_observability/tracing_observability.md)
- **axial coding**: Grouping error-analysis notes into piles and naming the piles after reading them, so failure modes emerge from data, not expectation. — first taught in [Day 44](Phase_5_Evaluation_and_Observability/Day_044_error_analysis/error_analysis.md)

## B

- **backend adapter (reference vs stub)**: A thin wrapper behind one setting: `reference` wraps the real R2-R4 modules, `stub` is keyless so CI can run the whole system. *SWE: ports and adapters.* — first taught in [Day 89](Phase_9_Production/Day_089_capstone_r5_integrate/capstone_r5_integrate.md)
- **background mode**: An OpenAI option (background=True) where the API returns immediately with status queued and you poll for the result of a long call. *SWE: ≈ submit-and-poll for a slow job* — first taught in [Day 78](Phase_9_Production/Day_078_async_jobs/async_jobs.md)
- **back-of-envelope estimate**: A one-minute calculation of whether a design is affordable and fast enough, driven by token counts rather than server counts. — first taught in [Day 97](Phase_11_Career_Launch/Day_097_system_design_interviews/system_design_interviews.md)
- **barge-in**: When the user speaks while the voice assistant is still talking, the assistant stops generating and trims the record to what was actually heard. — first taught in [Day 81](Phase_9_Production/Day_081_voice_realtime/voice_realtime.md)
- **baseline diff**: A per-criterion, per-case comparison of a pull request's eval scores against main's stored baseline scores. *SWE: ≈ a coverage diff on a PR* — first taught in [Day 47](Phase_5_Evaluation_and_Observability/Day_047_evals_in_ci/evals_in_ci.md)
- **baseline report**: Today's retrieval numbers by query kind, with misses listed and the case set fingerprinted, which later changes must beat. — first taught in [Day 29](Phase_3_RAG/Day_029_retrieval_evaluation/retrieval_evaluation.md)
- **baseline vs candidate**: Comparing a new model or approach (candidate) against the current one (baseline) on the same eval set before deciding to switch. *SWE: ≈ A/B comparison against current prod* — first taught in [Day 96](Phase_10_Open_Models_and_Fine_Tuning/Day_096_evaluating_distilling_small_models/evaluating_distilling_small_models.md)
- **Batch API**: An API that takes a JSONL file of requests and runs them offline at a discount, for work that can wait hours. *SWE: ≈ a nightly batch job* — first taught in [Day 18](Phase_2_Building_with_LLM_APIs/Day_018_cost_latency_caching/cost_latency_caching.md)
- **binary criterion**: A pass/fail rule for one failure mode with a passing and a failing example, preferred over 1-to-5 scores that drift between reviewers. — first taught in [Day 44](Phase_5_Evaluation_and_Observability/Day_044_error_analysis/error_analysis.md)
- **binary verdict**: A judge's pass-or-fail answer on one stated rule, which makes graders agree and each failure easy to explain. — first taught in [Day 45](Phase_5_Evaluation_and_Observability/Day_045_llm_as_judge/llm_as_judge.md)
- **bits per weight**: The average number of bits stored per model weight after quantization; real files land above the headline figure because of mixed precision. — first taught in [Day 92](Phase_10_Open_Models_and_Fine_Tuning/Day_092_quantization_hardware/quantization_hardware.md)
- **BM25**: A classic keyword-ranking formula that uses corpus statistics so rare words count more and long pages don't win by repetition. *SWE: ≈ the ranking inside a search engine* — first taught in [Day 27](Phase_3_RAG/Day_027_hybrid_search/hybrid_search.md)
- **BPE**: Byte-pair encoding: a tokenizer method that learns common character chunks from text and merges them into single tokens. — first taught in [Day 4](Phase_1_How_LLMs_Work/Day_004_tokens/tokens.md)
- **break-even volume**: The number of requests after which a fine-tuned or distilled small model's savings repay its one-time cost of labels, training, evals and your hours. — first taught in [Day 96](Phase_10_Open_Models_and_Fine_Tuning/Day_096_evaluating_distilling_small_models/evaluating_distilling_small_models.md)
- **budget**: The limit a stop condition enforces, such as 8 steps, 60 seconds, 100k tokens or 3 errors. *SWE: ≈ a timeout or resource quota* — first taught in [Day 48](Phase_6_Agents/Day_048_first_agent/first_agent.md)

## C

- **cache hit rate**: The share of input tokens read from the prompt cache; a higher rate means a lower input bill. *SWE: ≈ cache hit ratio* — first taught in [Day 18](Phase_2_Building_with_LLM_APIs/Day_018_cost_latency_caching/cost_latency_caching.md)
- **cache scope / invalidation**: The key parts that must match exactly (tenant, model, prompt version, index version) before a cached answer is reused, and the rules for expiring it. *SWE: ≈ cache keys and invalidation* — first taught in [Day 85](Phase_9_Production/Day_085_caching_cost_scale/caching_cost_scale.md)
- **call_id**: The identifier on a function_call item that you echo back on its function_call_output so the model can match each result to its request. *SWE: ≈ a correlation ID* — first taught in [Day 35](Phase_4_Tools_and_MCP/Day_035_function_calling/function_calling.md)
- **canary token**: A unique secret string planted in the system prompt; seeing it in output or tool arguments proves the prompt leaked. *SWE: ≈ a honeytoken* — first taught in [Day 69](Phase_8_Safety_and_Security/Day_069_prompt_injection/prompt_injection.md)
- **canary with guard metrics**: Release a change to a small share of traffic and promote, hold or roll back based on guard metrics measured on that slice. *SWE: ≈ canary deploy with health checks* — first taught in [Day 87](Phase_9_Production/Day_087_shipping_changes_safely/shipping_changes_safely.md)
- **cancellation**: Stopping a streaming response early because the user pressed Ctrl-C or only needed a preview, so you stop paying for tokens. — first taught in [Day 13](Phase_2_Building_with_LLM_APIs/Day_013_streaming/streaming.md)
- **candidate pool**: How many first-stage retrieval results you hand to the reranker (20 in the lesson), before it keeps the top-n. — first taught in [Day 31](Phase_3_RAG/Day_031_reranking_contextual_retrieval/reranking_contextual_retrieval.md)
- **chained voice pipeline**: A voice design that chains speech-to-text, your normal text agent, then text-to-speech, so existing text logic runs unchanged in the middle. *SWE: ≈ a pipeline of three services* — first taught in [Day 81](Phase_9_Production/Day_081_voice_realtime/voice_realtime.md)
- **chain-of-thought**: Prompting the model to write its intermediate steps in the visible reply before the final answer, trading extra tokens for accuracy. — first taught in [Day 11](Phase_2_Building_with_LLM_APIs/Day_011_reasoning_cot/reasoning_cot.md)
- **chat template**: The model's own rules for turning system, user and assistant messages into one string of special tokens, which must match at training and inference. — first taught in [Day 95](Phase_10_Open_Models_and_Fine_Tuning/Day_095_lora_finetuning/lora_finetuning.md)
- **checkpointer / checkpoint**: The storage backend (in-memory, SQLite, Postgres) that saves a graph's state after each step, so a run can resume or replay. *SWE: ≈ a saved game or DB snapshot* — first taught in [Day 54](Phase_6_Agents/Day_054_langgraph_durability/langgraph_durability.md)
- **chunk**: A contiguous slice of a document that you embed, store and retrieve as one unit. — first taught in [Day 25](Phase_3_RAG/Day_025_chunking/chunking.md)
- **chunk size**: The maximum length of a chunk, counted in tokens, which trades retrieval precision against context. — first taught in [Day 25](Phase_3_RAG/Day_025_chunking/chunking.md)
- **circuit breaker**: Stop calling a failing service for a while, then let one probe request test whether it has recovered. *SWE: ≈ the same pattern in microservices* — first taught in [Day 84](Phase_9_Production/Day_084_reliability_fallbacks/reliability_fallbacks.md)
- **citation**: A pointer from a claim in the answer back to its source, such as a doc id plus a quote, so answers are checkable. *SWE: ≈ a footnote you can verify* — first taught in [Day 28](Phase_3_RAG/Day_028_rag_pipeline/rag_pipeline.md)
- **citation check**: Code that proves every cited id and quote in an answer actually exists in the retrieved evidence. *SWE: ≈ a foreign-key check on citations* — first taught in [Day 61](Phase_6_Agents/Day_061_capstone_r3_investigator/capstone_r3_investigator.md)
- **client disconnect**: When the client goes away mid-stream, the server cancels the generator and stops work, so you don't pay for tokens nobody reads. — first taught in [Day 77](Phase_9_Production/Day_077_fastapi_serving/fastapi_serving.md)
- **client-side rate limiting**: Throttling your own calls with a token bucket, a counter refilled at a fixed rate that each call spends from, to stay under provider limits. *SWE: ≈ a token-bucket limiter* — first taught in [Day 84](Phase_9_Production/Day_084_reliability_fallbacks/reliability_fallbacks.md)
- **code-based check**: A small function that compares one output field to the gold answer and returns pass or fail, with no model involved. *SWE: ≈ a unit-test assertion* — first taught in [Day 20](Phase_2_Building_with_LLM_APIs/Day_020_first_eval_set/first_eval_set.md)
- **code interpreter container**: A hosted sandbox, an isolated virtual machine, where the model writes and runs Python; it expires after 20 minutes idle. — first taught in [Day 38](Phase_4_Tools_and_MCP/Day_038_built_in_tools/built_in_tools.md)
- **coding agent**: An agent loop with tools to read a file, edit a file and run a shell command, which edits, runs tests and retries until done. — first taught in [Day 60](Phase_6_Agents/Day_060_coding_agents_skills/coding_agents_skills.md)
- **coercion**: Pydantic's automatic conversion of a compatible value to the declared type ("37" to 37); strict mode turns it off for model output. — first taught in [Day 15](Phase_2_Building_with_LLM_APIs/Day_015_pydantic_for_llms/pydantic_for_llms.md)
- **cold-clone check**: Cloning your repo onto a fresh machine and running it from the README alone, to catch hidden dependencies before a reviewer does. *SWE: ≈ a clean-room build test* — first taught in [Day 99](Phase_11_Career_Launch/Day_099_portfolio/portfolio.md)
- **compaction**: Replacing many old context items with one compact summary, written by you or produced by the server as an opaque item. — first taught in [Day 49](Phase_6_Agents/Day_049_context_engineering/context_engineering.md)
- **compile**: In LangGraph, turning a graph definition into a runnable graph, optionally attaching a checkpointer. *SWE: ≈ building a pipeline before running it* — first taught in [Day 53](Phase_6_Agents/Day_053_langgraph_graphs/langgraph_graphs.md)
- **component registry**: A dict from allowed UI component names to typed props models, from which tools, validation and templates are derived so the model can only emit approved components. *SWE: ≈ an allowlist of renderable widgets* — first taught in [Day 80](Phase_9_Production/Day_080_generative_ui/generative_ui.md)
- **composition root**: The single place where every long-lived object is built and wired together (here `build_deps()`), so tests can swap one part and one place shows what's live. *SWE: DI container setup.* — first taught in [Day 89](Phase_9_Production/Day_089_capstone_r5_integrate/capstone_r5_integrate.md)
- **compounding error**: Small per-step failure rates multiplying across a chain: five hops at 95% each are all right only about 77% of the time. — first taught in [Day 64](Phase_7_Multi_Agent_Systems/Day_064_multi_agent_when/multi_agent_when.md)
- **computer-use agent**: A model that operates a screen: it sees a screenshot, chooses an action such as click or type, your code performs it, and you send back the next screenshot. — first taught in [Day 72](Phase_8_Safety_and_Security/Day_072_sandboxing_computer_use/sandboxing_computer_use.md)
- **concurrency limit**: The maximum number of tasks allowed to run at once, enforced with a semaphore. *SWE: ≈ a thread-pool size* — first taught in [Day 22](Phase_2_Building_with_LLM_APIs/Day_022_capstone_r1_extractor/capstone_r1_extractor.md)
- **concurrency sweep**: A load test run at several fixed levels of in-flight requests (1, 4, 16, 32) to see where throughput stops growing. — first taught in [Day 93](Phase_10_Open_Models_and_Fine_Tuning/Day_093_vllm_serving/vllm_serving.md)
- **conditional edge**: A graph edge backed by a small function that reads the state and picks the next node. *SWE: ≈ a branch or switch statement* — first taught in [Day 53](Phase_6_Agents/Day_053_langgraph_graphs/langgraph_graphs.md)
- **conformity flip**: A debater changing its answer to match its peers; good flips go wrong to right, bad flips go right to wrong. — first taught in [Day 67](Phase_7_Multi_Agent_Systems/Day_067_debate_multi_agent_ops/debate_multi_agent_ops.md)
- **confused deputy**: A server with broad power of its own uses it on behalf of a caller who lacks that permission. — first taught in [Day 74](Phase_8_Safety_and_Security/Day_074_least_privilege_mcp_security/least_privilege_mcp_security.md)
- **confusion table**: A 2x2 count of human verdict against judge verdict, from which you read the judge's true-positive and true-negative rates. *SWE: ≈ a classifier's confusion matrix* — first taught in [Day 46](Phase_5_Evaluation_and_Observability/Day_046_judge_validation/judge_validation.md)
- **consensus rule**: How the last debate round becomes one answer: majority vote, or a judge call picking the best-supported answer. — first taught in [Day 67](Phase_7_Multi_Agent_Systems/Day_067_debate_multi_agent_ops/debate_multi_agent_ops.md)
- **constrained decoding**: At each step the server allows only tokens that keep the output inside a schema, so required keys can't go missing and enums stay valid. *SWE: ≈ a grammar-enforced parser* — first taught in [Day 96](Phase_10_Open_Models_and_Fine_Tuning/Day_096_evaluating_distilling_small_models/evaluating_distilling_small_models.md)
- **container escape**: An attacker breaking out of a container to reach the host; run as non-root and drop kernel capabilities to make it harder. — first taught in [Day 72](Phase_8_Safety_and_Security/Day_072_sandboxing_computer_use/sandboxing_computer_use.md)
- **content hash**: A short fingerprint that changes whenever the text changes, used to prove a prompt version wasn't altered. *SWE: ≈ a git object hash* — first taught in [Day 21](Phase_2_Building_with_LLM_APIs/Day_021_prompts_as_code/prompts_as_code.md)
- **content-hash id**: A row id computed from the content itself (a SHA-256 hash), so the same text always gets the same id and upserts are idempotent. — first taught in [Day 26](Phase_3_RAG/Day_026_pgvector_search/pgvector_search.md)
- **content part**: One small dict with a type inside a message's content list, used to mix text, images and files in one request. — first taught in [Day 14](Phase_2_Building_with_LLM_APIs/Day_014_multimodal_inputs/multimodal_inputs.md)
- **Content Security Policy**: A browser-enforced policy header that limits which scripts and resources a page may load, reducing damage from injected output. *SWE: ≈ a firewall for the browser page* — first taught in [Day 71](Phase_8_Safety_and_Security/Day_071_safe_output_handling/safe_output_handling.md)
- **context budget**: The number of tokens you allow one request to use, a cost and quality choice well below the model's maximum window. — first taught in [Day 49](Phase_6_Agents/Day_049_context_engineering/context_engineering.md)
- **context isolation**: Giving each sub-agent its own clean context so it works without the noise of other agents' history. *SWE: ≈ process isolation, each with its own memory* — first taught in [Day 64](Phase_7_Multi_Agent_Systems/Day_064_multi_agent_when/multi_agent_when.md)
- **context relevance**: An answer-quality check asking whether the retrieved context actually contains what is needed to answer the question. *SWE: ≈ did the query return the right rows* — first taught in [Day 30](Phase_3_RAG/Day_030_answer_evaluation/answer_evaluation.md)
- **context rot**: Answer quality that degrades as the context gets longer, even when everything fits in the window, because the model does not use all of it equally well. — first taught in [Day 5](Phase_1_How_LLMs_Work/Day_005_transformers_attention/transformers_attention.md)
- **contextual chunk header**: A short label, such as the page title and section, added to a chunk so it still makes sense once cut out of its page. *SWE: ≈ a breadcrumb on each search result* — first taught in [Day 25](Phase_3_RAG/Day_025_chunking/chunking.md)
- **contextual retrieval**: Adding context about where a chunk came from to the chunk before indexing, so retrieval can match chunks that are ambiguous on their own. — first taught in [Day 31](Phase_3_RAG/Day_031_reranking_contextual_retrieval/reranking_contextual_retrieval.md)
- **context window**: The maximum amount of text, counted in tokens, a model can take in and produce in one request; you budget it. *SWE: ≈ a maximum request body size* — first taught in [Day 5](Phase_1_How_LLMs_Work/Day_005_transformers_attention/transformers_attention.md)
- **continuous batching**: A serving technique where the scheduler adds and removes requests from the running GPU batch at every step instead of waiting for a whole batch to finish. *SWE: ≈ a thread pool that refills slots instantly* — first taught in [Day 93](Phase_10_Open_Models_and_Fine_Tuning/Day_093_vllm_serving/vllm_serving.md)
- **contract snapshot test**: A test that saves every tool's name, arguments and return shape to a committed file and fails when any of them changes unexpectedly. *SWE: ≈ an API schema snapshot test* — first taught in [Day 40](Phase_4_Tools_and_MCP/Day_040_mcp_servers/mcp_servers.md)
- **conversation state**: Everything said so far in a conversation, which your code stores and re-sends so the model can continue it. *SWE: ≈ session state* — first taught in [Day 8](Phase_2_Building_with_LLM_APIs/Day_008_messages_and_state/messages_and_state.md)
- **correlated errors**: Mistakes shared by several model calls, for example the same model with the same prompt, so voting or debate gains far less than independent errors would give. — first taught in [Day 67](Phase_7_Multi_Agent_Systems/Day_067_debate_multi_agent_ops/debate_multi_agent_ops.md)
- **cosine similarity**: A score from -1 to 1 for how closely two vectors point the same way; higher means more similar in meaning. — first taught in [Day 23](Phase_3_RAG/Day_023_embeddings/embeddings.md)
- **cost-tiered judging**: Running a cheap judge or code check first and sending only uncertain cases to a stronger, pricier judge, to keep evaluation affordable. *SWE: ≈ a cheap linter before a slow test suite* — first taught in [Day 45](Phase_5_Evaluation_and_Observability/Day_045_llm_as_judge/llm_as_judge.md)
