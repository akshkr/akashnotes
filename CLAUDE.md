# CLAUDE.md: Working on this repository

This orients Claude (and any AI assistant) to what this repo is, how it's built, and the rules
for editing it. Read it before making changes.

## 1. What this is
This is a **100-day course that turns software engineers and freshers into AI / LLM-application
engineers**, written as Markdown lessons. A separate frontend renders it: Mermaid becomes diagrams,
and Python blocks are syntax-highlighted and **extracted and executed**.

- **Audience:** working SWEs (each lesson has a fast path) and freshers (define-before-use, plus
  appendix primers).
- **Core device:** translate each AI concept into something an engineer already knows. That's the
  `> **Coming from Software Engineering?**` callout, with a plain-language version in the main text.
- **The product thread:** learners build **Atlas**, an assistant for the maintainers of **Orbit**.
  Orbit is a fictional open-source jobs library; its data lives in `datasets/orbit/`. Atlas ships in
  five releases (R1 D22, R2 D34, R3 D61–62, R4 D76, R5 D89–90).
- This repo is **content only**, plus the small `tools/` that verify it.

## 3. The `script_id` model (read before editing code)
- Every Python block starts with `# script_id: day_NNN_<slug>/<name>`. Blocks that share an id are
  **stitched in document order into one file**, which must run top to bottom.
- **Multi-file projects:** used by capstones, and by some lessons for helpers. Give each file its
  own id named by module path, e.g. `day_022_capstone_r1_extractor/atlas/schemas`. Files import each
  other as packages (`from atlas.schemas import …`).
- Never import a name from a module whose code sits in the *same* id.
- Non-runnable illustrations carry `# fragment`.
- Learners copy this code into real projects, so it must be correct and current. A wrong API costs
  their trust.

## 4. Providers and facts
- **OpenAI is primary**: SDK 3.x, the **Responses API** (`client.responses.*`), the GPT-6 lineup.
  The default model is `gpt-6-luna`, read from `ATLAS_MODEL`. Chat Completions appears only as a
  labelled legacy comparison.
- **Anthropic appears only in D2 and D7**, as a comparison: the 5.x IDs, bare aliases.
- **Never guess an API, parameter, model ID, price or URL.**
  - Verify it against `REFERENCE.md`, by introspecting the installed package, or against the
    official docs.
  - If you can't verify it, omit it, or describe it with "⚠ verify against current docs".
  - Every price says "as of <date>, verify".
- Things that are retired or closing are never taught. The list is in `REFERENCE.md`.

## 5. Lesson anatomy and budget
These follow `STYLE_GUIDE.md` §2 exactly:
1. Hook
2. At a Glance (time · prereqs · build · stops at · **fast path** · **cost** · new terms)
3. The SWE callout
4. The core ladder (problem → intuition → tiny example → name the parts + diagram → minimal code →
   break it → realistic version → trade-offs / in production)
5. **Go Deeper (optional)** `<details>` blocks
6. Common Pitfalls
7. The "Where we stop" box
8. Key Takeaways (5)
9. Quick Reference
10. Exercises (3 + 1 stretch, collapsible solutions)
11. References & Further Reading
12. What's Next (links the next day)

**Budget, about 2 h core:** 2,000–3,000 words of core prose, usually 7–8 body scripts (max 10;
capstones about 12, max 15), and Go Deeper ≤1,500 words.

## 6. Maintenance workflow
1. **Facts first:** change `REFERENCE.md`, then every lesson that restates the fact, then add a
   `CHANGELOG.md` line.
2. **Gates.** CI runs these:
   ```bash
   python3 tools/lesson_check.py . --budget          # fences, script_ids, stitched-import bug, deprecated APIs, template, budget
   python3 tools/lesson_check.py <file> --mermaid    # render every diagram (needs mmdc)
   python3 tools/run_scripts.py <file>               # extract + run every script; reports "needs key/service" separately
   python3 tools/course_qa.py                        # internal links, What's Next chain, no forward prerequisites
   python3 tools/lesson_check.py <file> --online     # external links (tolerates TLS-intercepting proxies)
   ```
3. **The syllabus changed?** Regenerate `index.md` with `python3 tools/build_index.py`.
4. **Cross-references:** when you touch a day, check its prereqs and What's Next against the day map.

## 7. Rules
**Do:**
- Keep code runnable and current.
- Keep `script_id` grouping intact.
- Match the template and the budget.
- Put advanced material in Go Deeper rather than growing the core.
- Use the Atlas module names in `STYLE_GUIDE.md` §6.
- Teach an owned topic once (§7); other days link to its owner.
- Surface anomalies instead of silently proceeding.

**Don't** (without explicit owner approval):
- Renumber, add or merge days.
- Swap the primary provider.
- Change capstone module paths that later days import.
- Fabricate SDK APIs.
- Commit or push unless asked.
